# MCP harness interoperability

**Scope:** Archestra acts as the MCP **server** at `/v1/mcp/<gateway>`. It uses Streamable HTTP with OAuth and/or authorized bearer tokens. The gateway speaks both the legacy `2025-11-25` initialize lifecycle and the `2026-07-28` stateless discovery lifecycle. This is protocol compatibility, **not** proof that every agent product supports the transport and authorization mode.

## Protocol smoke tests

Start Archestra, create a gateway, assign at least one **read-only** tool, generate a narrowly scoped user or service token, then set these environment variables without checking credentials into Git or printing them:

```bash
export ARCHESTRA_MCP_URL=http://127.0.0.1:9000/v1/mcp/my-gateway
read -r -s ARCHESTRA_MCP_TOKEN
export ARCHESTRA_MCP_TOKEN
node platform/scripts/mcp-smoke.mjs
unset ARCHESTRA_MCP_TOKEN
```

The probe verifies an unauthenticated `tools/list` request is denied, an authenticated legacy initialization works, modern `server/discover` works, and each revision can list tools. It **never calls tools**, even if they have side effects. For specific clients, run the connection instructions in the Connect page and then confirm a real authorized read-only call plus an unauthorized call denial. Keep audit logs and client versions.

A local `http://127.0.0.1` gateway is suitable for testing on the same host. Remote harnesses require reachable HTTPS and correct OAuth protected-resource metadata, issuer, redirect and token audience settings. Avoid tunneling an unauthenticated developer gateway to the internet.

## Compatibility acceptance matrix

For each harness/version, record:

1. Installation/version and exact configuration generated by the current client.
2. Transport: Streamable HTTP preferred; authenticated stdio bridge only if required.
3. Auth: OAuth sign-in/refresh or scoped bearer; unauthorized calls produce 401/403.
4. Wire: initialize or discover, `tools/list`, tool schema, streaming and reconnect.
5. Policy: allowlisted tool succeeds, denied tool fails, no cross-user credential leakage.
6. Result: **PASS**, **FAIL**, or **NOT TESTED** with timestamp and redacted evidence.

Security note: client support for MCP tools does **not** imply it can route its LLM traffic through Archestra's Bedrock or Ollama proxy. Treat MCP and LLM provider integration as separate product capabilities.
